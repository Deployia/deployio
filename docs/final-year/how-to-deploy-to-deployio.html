How to Deploy to Deployio

One-page guide · deployio.tech · Final-year / developer reference

What Deployio Does

Connects to Git (GitHub, GitLab, Azure DevOps), discovers Dockerfiles, analyzes each service, builds a container, and hosts it at https://<subdomain>.deployio.tech.

Important: docker-compose.yml is not run for hosting. Deploy one service per project — each with its own Dockerfile.

Repository Layouts

Single service — Dockerfile at repo root; build context = .

my-app/
├── Dockerfile
├── package.json
└── src/

Multi-service — one Dockerfile per folder; one Deployio project each.

my-platform/
├── frontend/Dockerfile
├── backend/Dockerfile
└── docker-compose.yml  (local only)

Build context: directory containing the chosen Dockerfile — not always repo root. COPY paths must live inside that folder.

PatternExample
RootDockerfile
Service dirbackend/Dockerfile
VariantDockerfile.prod

Dockerfile Requirements

  • Required: FROM + CMD or ENTRYPOINT
  • Recommended: ENV PORT, EXPOSE, listen on 0.0.0.0, /health or HEALTHCHECK
  • Env hints: .env.example beside the Dockerfile

Multi-Service Checklist

  1. Dockerfile per service (frontend, API, worker)
  2. Project A: select frontend/Dockerfile → deploy
  3. Project B: same repo, backend/Dockerfile → wire URLs & secrets
